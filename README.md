# 통합업무지시 솔루션

영업 · 고객 · 행정 · 인사 — 8개 지사 통합 업무지시/모니터링/평가보상 플랫폼 프로토타입 (서버 없는 프론트엔드 데모)

배포 주소: [heebonpark.github.io/task-order-solution](https://heebonpark.github.io/task-order-solution/)

운영메뉴얼: [heebonpark.github.io/task-order-solution/manual.html](https://heebonpark.github.io/task-order-solution/manual.html) — 회사 네트워크에서 claude.ai가 차단될 경우 이 주소를 사용하세요 (앱과 같은 도메인).

담당지사·역할(SP/SE/SG/지사장/영업팀장/고객팀장/지사내근/본부장/사업지원팀장/담당자)을 화면 상단에서 선택하면 그 역할 기준으로 화면이 바뀝니다.

## 공유용 링크

역할별로 바로 원하는 화면으로 진입할 수 있도록 링크를 나눠뒀습니다. (진입 후에도 상단에서 지사/역할을 자유롭게 바꿀 수 있습니다)

| 대상 | 링크 | 설명 |
| --- | --- | --- |
| 업무지시 (중간관리부서·본부) | [`?v=orders`](https://heebonpark.github.io/task-order-solution/?v=orders) | 업무지시 등록/목록 화면으로 바로 진입 (기본 역할: 담당자) |
| 중간모니터링 (지사장·영업팀장·고객팀장·지사내근) | [`?v=branch`](https://heebonpark.github.io/task-order-solution/?v=branch) | 본인 지사로 스코프 제한된 대시보드로 바로 진입 (기본 역할: 지사장) |
| 본부 모니터링 | [`?v=monitor`](https://heebonpark.github.io/task-order-solution/?v=monitor) | 전 지사 대시보드로 바로 진입 (기본 역할: 본부장) |
| 수행자 (SP·SE·SG 현장) | [`?v=exec`](https://heebonpark.github.io/task-order-solution/?v=exec) | 본인 업무 목록으로 바로 진입 (기본 역할: SP) |

수행자 링크는 역할/지사/구역을 URL에 직접 지정할 수도 있습니다. 예: `?v=exec&r=SE&b=강릉&z=교동` (강릉지사 교동구역 SE로 진입)

## 추가 기능

- **관리자 모드**: 화면 상단 "관리자" 비밀번호 입력 시 전 지사·전 권한(업무지시 수정/삭제, 전 지사 수행자 관리 포함)으로 전환됩니다. 비밀번호는 담당자에게 별도로 전달받으세요. ⚠️ 서버 없는 프론트엔드 데모라 이 잠금은 화면(페이지 소스)에서 우회 가능한 UI 편의 기능이며, 실제 접근 통제가 아닙니다.
- **수행자 관리**: 중간관리부서는 본인 지사, 관리자는 전 지사의 SP·SE·SG 인원을 등록/삭제할 수 있습니다.
- **수행 등록 강화**: 현장 수행자는 지시별로 조치결과(진행중/완료/기타), 특이사항, 사진촬영, 첨부파일을 등록할 수 있습니다.
- **인사이트 · 개선 제안**: 중간관리부서·본부·관리자에게만 보이는 탭으로, 대구분(영업/고객/행정/인사)별 지시 분포와 지연율·완료율, 지사 과부하·결원을 규칙 기반으로 자동 분석해 개선 제안을 보여줍니다. 데이터가 바뀔 때마다 다시 계산되고, 주의가 필요한 항목이 있으면 탭에 배지로 표시됩니다. 중간관리자는 본인 지사, 본부/관리자는 전 지사 기준입니다.
- **현장 업무지시 등록**: SP·SE·SG도 이제 `업무지시` 탭을 볼 수 있어, 배정을 기다리지 않고 현장에서 발견한 업무를 직접 등록할 수 있습니다. 등록 화면을 열면 대상 직급·구역이 본인 것으로 자동 지정되어(전체 흩뿌리기 아님) 바로 제목·마감일만 채우면 됩니다.
- **담당구역**: 지사 아래 세부 단위로 지사당 2개 구역(예: 중앙 → 종로동·명동)을 두고, 수행자 관리에서 인원마다 담당구역을 지정합니다. 현장 화면 상단에 담당지사·역할과 함께 담당구역 선택이 추가되어, 같은 지사·같은 역할이라도 구역이 다르면 서로의 업무가 섞이지 않습니다. 업무지시 등록 시 특정 구역을 지정하면 대상 지사가 자동으로 그 구역의 지사 하나로 고정됩니다. 원주(춘천) 지사는 원주 단계동·춘천 퇴계동 두 구역으로, 두 도시를 함께 관할하는 이유가 구역 단위에도 드러납니다.
- 지사 목록의 "원주"는 "원주(춘천)"으로 표기됩니다.

## 시뮬레이션으로 발견 · 수정한 문제

기능을 추가할 때마다 실제 클릭·입력을 재현하는 시뮬레이션을 돌려 검증합니다. 담당구역 도입 시 이렇게 잡아낸 문제:

- **미확인 배지 누수**: 같은 지사·같은 역할이지만 구역이 다른 두 수행자가 서로의 "새 지시 확인 여부"를 공유하던 문제. 배지 판별 키에 구역을 포함시켜 수정.
- **업무지시 등록 시 대상 기본값**: 현장 담당자가 업무지시 탭에서 직접 등록할 때 대상 직급이 "전체"로 기본 설정되어 있어, 본인이 발견한 문제인데도 지사 전체에 알림이 가던 문제. 본인 역할·구역으로 기본 지정되도록 수정(입력 중인 내용은 덮어쓰지 않음).
